I found five remaining integration issues. No source files were changed.
1. [P2] Saving still overwrites a strategy’s recorded perk requirements.
   The editor replaces monkey_knowledge and more_starting_cash with values derived from the local settings toggle.
   Reproduced: A valid draft requiring $850 starting cash passed replay validation. Running the actual save callback with the local toggle off rejected it with:
   Starting cash is 850, expected 650.
   Opening cost $695 exceeds $650 starting cash.
   This means an unrelated edit can make an otherwise valid imported guide impossible to save.
   The threat radar also uses the local toggle rather than the strategy’s independent perk requirements, producing the same disagreement.
   Improve: Preserve recorded requirements unless the user explicitly edits them. Pass the same resolved perk configuration to saving, replay, and radar.
   References: [editor save (line 3218)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/btd6_guide.pyw:3218), [radar (line 2691)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/btd6_guide.pyw:2691).
2. [P2] Regeneration changes free-tower prices incorrectly.
   The generator’s cost-synchronization engine is created without the strategy’s perk settings.
   Reproduced: Regenerating an override with free_dart_monkey: true changed its first Dart Monkey’s displayed cost from $0 to $170. Replaying the generated strategy still calculated $0.
   The generated instructions and validation therefore disagree about the purchase cost.
   Improve: Resolve requirements before cost synchronization and use identical settings for synchronization and final validation.
   Reference: [generate_guides_database.py (line 97)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/generate_guides_database.py:97).
3. [P2] ID assignment can attach an upgrade to an already-sold tower.
   assign_explicit_tower_ids() skips processing Upgrade, Target, and Sell actions when they already have an ID. Consequently, its internal list of active towers does not reflect explicit sales or upgrades.
   Reproduced sequence:
   - Place Dart Monkeys identified as first and second.
   - Sell first using its explicit ID.
   - Upgrade the remaining Dart Monkey without an ID.
   Replay accepted the original sequence. ID assignment then attached the upgrade to first, and validation rejected it as referencing an inactive tower.
   Improve: Update the internal tower state for every explicit action. Only skip ID inference, not state tracking.
   Reference: [btd6_replay.py (line 590)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/btd6_replay.py:590).
4. [P2] The generator and standalone validator still disagree about drafts.
   The generator now permits tactical warnings for drafts, but validate_database() always requests strict tactical validation.
   Reproduced: Generation successfully wrote a database containing a one-step draft. Validating that same generated file failed on its missing camo, lead, and MOAB coverage.
   Improve: Decide whether drafts belong in the generated database. Either preserve them and report tactical warnings consistently, or explicitly separate drafts from release-ready output. Apply that policy across both tools.
   Reference: [validate_guides.py (line 111)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/validate_guides.py:111).
5. [P2] Exported requirements misdescribe independent perks.
   The replay engine now supports separate perks, but Markdown and HTML still describe Monkey Knowledge as “More Starting Cash.”
   Reproduced: A strategy requiring only a free Dart Monkey exported:
   Monkey Knowledge: Enabled (More Starting Cash)
   Min Starting Cash: $650
   It omitted the actual free-Dart requirement and named a perk explicitly disabled in the strategy.
   Improve: Export each requirement separately: starting cash, More Starting Cash, and Free Dart Monkey. Derive all formats from one formatter.
   References: [Markdown requirements (line 2031)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/btd6_guide.pyw:2031), [HTML requirements (line 2103)](C:/Users/rodge/OneDrive/Desktop/BTD6_Guide/btd6_guide.pyw:2103).
